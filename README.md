# USB Agent — фоновый подсказчик для браузера

Локальная нейросетевая модель + агент на Python, который читает
содержимое активной вкладки Chrome и даёт **очень тонкие подсказки**
прямо в страницу (курсив одной буквы, микро-подсветка, микро-сдвиг).
Не решает задачу за тебя — только намекает.

Есть два режима работы:

1. **Общие подсказки** (локальная LLM первично, облако — по запросу).
   Для произвольных страниц: подсвечивает, что стоит поправить.
2. **Решение тестов** (`cloud_first: true`) — мощный режим для страниц
   с radio/checkbox-вопросами. Облако (OpenRouter или Gemini) видит
   структурированную карту теста, выбирает правильные ответы и
   подсвечивает их серым фоном. Локальная LLM — только fallback.

Цели:
- работает с флэшки, ничего не устанавливает на хост,
- малая модель (1–3B параметров) — запустится даже на слабом железе,
- фоновый режим, без диалоговых окон,
- облако решает первично; локальная модель подхватывает, если облако
  не ответило.

## Архитектура

```
   Chrome (--remote-debugging-port=9222)
                │
                │ WebSocket (CDP)
                ▼
        ┌─────────────────┐
        │  agent main.py  │  ←─── task.txt (задача, можно менять на лету)
        └─────────────────┘
           │            │
           │ cloud_first │ needs_external (когда локальная модель просит)
           ▼            ▼
   llama-server    OpenRouter / Gemini
   (локально,      (+ веб-поиск)
   fallback)       api.openrouter.ai / generativelanguage.googleapis.com
           │            │
           └─────┬──────┘
                 ▼
   cdp_client.get_test_structure()  →  маркирует DOM (data-usb-q-index,
                                       data-usb-option) на input и img
                 ▼
   injector.apply_hints()  →  Runtime.evaluate  →  тонкие правки DOM
   (поиск по dataset-маркерам, не по тексту/порядку групп)
```

### Поток цикла (режим `cloud_first`)

1. Опрос активной вкладки каждые `poll_interval_seconds`. Если контент
   не изменился → ждём.
2. `cdp_client.get_test_structure()` проходит по всем `input[type=radio]`
   и `input[type=checkbox]`, группирует их в вопросы, извлекает текст
   вопроса и вариантов, и **маркирует DOM** через `dataset`-атрибуты
   (см. ниже).
3. Облако получает задачу + структурированную карту теста + текст
   страницы, возвращает JSON `{"hints": [{"question_index", "find_text",
   "action": "background_tint"}]}`.
4. `deduplicate_hints()` валидирует каждый hint: `find_text` должен быть
   в `options` своего вопроса; если нет — перемещается в правильный
   вопрос. radio → 1 ответ, checkbox → ≤2–3.
5. `injector.apply_hints()` находит элемент по `dataset`-маркерам
   (`data-usb-q-index` + `data-usb-option`) и применяет подсветку.
6. `answer_unanswered_via_cloud()` — **второй проход**: вопросы, на
   которые облако не ответило в первом запросе, отправляются повторно
   компактным JSON. Сопоставление `find_text`↔`options` идёт с
   нормализацией (`Math::PI`→`π`, `·`→`*`) и fuzzy-matching
   (Левенштейн).

Если облако не ответило (сеть/лимит) — fallback на локальную LLM.
В режиме без `cloud_first` локальная LLM работает первично и может
попросить облачный поиск через `needs_external`.

## Универсальное извлечение структуры теста

`cdp_client.get_test_structure()` не зависит от разметки страницы
(Moodle, рукописный HTML, формулы как `<img alt="...">`,
radio+checkbox+text-input вперемешку — всё работает).

**Группировка вопросов** — по наименьшему общему предку, содержащему
≥2 input'ов того же типа, а не по атрибуту `name` (у Moodle-checkbox'ов
`name` свой для каждого варианта, и старая группировка по `name`
превращала 5 вариантов одного вопроса в 5 «вопросов» с 1 вариантом).
Блоки сортируются в DOM-порядке, поэтому `question_index` идёт сверху
вниз по странице.

**Текст варианта** — 8 уровней fallback:
1. `label[for="ID"]` внутри блока,
2. `inp.closest('label')`,
3. `nextElementSibling` (первые 5 соседей),
4. ближайший предок с текстом (но не блок),
5. text-сиблинги (text nodes и элементы без input'ов),
6. предыдущий сиблинг (текст может быть перед input),
7. `img[alt]` внутри блока по позиции после input,
8. любой элемент после input в DOM-порядке.

«Текст» элемента берётся через `getElementText()`: `textContent` →
`img.alt` → первый `img[alt]` внутри → `title` → `aria-label`. Это
покрывает формулы, отрисованные как `<img alt="\frac{\pi}{180}g">`
(MathJax/MathML).

**Маркировка DOM** — постоянные маркеры, которые инжектор ищет потом:
- `input.dataset.usbQIndex` / `input.dataset.usbOption` — на каждом
  input'е варианта,
- `img.dataset.usbQIndex` / `img.dataset.usbOption` — на картинке,
  если текст взят из её `alt`.

Инжектор ищет элемент по `data-usb-q-index === qIndex` И
`data-usb-option === normFind`, затем находит обёртку (`closest('label')`
или ближайший предок без других input'ов) и применяет подсветку.
Это **не зависит от порядка групп** и от HTML-структуры — короткие
ответы вроде `"4"`, `"=="`, `"||"` подсвечиваются именно в своём
вопросе, а не в первом попавшемся.

## Что нужно скачать вручную

Тяжёлые бинарники и модели в этот пакет не входят — их кладёшь
в `usb_agent/` сам.

### 1. `llama-server` из llama.cpp

- Страница релизов: https://github.com/ggml-org/llama.cpp/releases
- Windows (CPU, универсальный): скачай `llama-bXXXX-bin-win-cpu-x64.zip`.
  В архиве лежит `llama-server.exe` (тонкий загрузчик ~9 КБ) + набор
  `.dll`, включая **15 `ggml-cpu-*.dll`** под разные микроархитектуры
  (alderlake, haswell, zen4, sandybridge, sse42 и т.д.) — ggml сам
  определит твой процессор при запуске и подгрузит нужную.
  Распакуй **всю папку целиком** в `usb_agent/llama/`.
- Windows (NVIDIA GPU): `llama-bXXXX-bin-win-cuda-cu12.4-x64.zip`
  (или `cuda-cu13.5`). Логика та же — вся папка в `usb_agent/llama/`.
- Windows (AMD/Intel GPU без CUDA): `llama-bXXXX-bin-win-vulkan-x64.zip`.
- Linux: `llama-bXXXX-bin-ubuntu-x64.zip` → распакуй в `usb_agent/llama/`.
- macOS: `llama-bXXXX-bin-macos-*-metal.zip`.

> **ВАЖНО**: `llama-server.exe` — это загрузчик ~9 КБ, основная логика
> в `llama-server-impl.dll` (~10 МБ). Нельзя вытащить только `.exe` —
> нужна вся папка.

Проверь, что бинарь запускается:
```cmd
llama\llama-server.exe --help
```

### 2. GGUF-модель

Положи `.gguf` в папку `models/`. Рекомендуемые варианты
(Q4_K_M — хороший баланс размера и качества):

| Модель | Диск | ОЗУ | Когда |
| --- | --- | --- | --- |
| Llama-3.2-1B Instruct Q4 | ~0.7 ГБ | ~1.2 ГБ | совсем слабое железо |
| **Qwen2.5-3B Instruct Q4_K_M** | ~2.0 ГБ | ~2.5 ГБ | по умолчанию |
| Phi-3-mini-4k Q4 | ~2.3 ГБ | ~2.8 ГБ | если 3B мало соображает |

Имя файла значения не имеет — `run.bat` / `run.sh` берёт
первый попавшийся `.gguf` из `models/`.

### 3. Python 3.8+ и одна зависимость

```bash
pip install -r requirements.txt
```

Нужен только `websocket-client`. Для портативного запуска на Windows
можно положить рядом распакованный embeddable Python.

### 4. Ключ облачного провайдера

По умолчанию используется **OpenRouter** (`cloud.provider: "openrouter"`):
нет региональных блоков, есть free-tier, регистрация через GitHub/Google
без карты.

1. Открой https://openrouter.ai/keys → **Create Key**.
2. Скопируй ключ вида `sk-or-v1-...`.
3. Вставь его в `config.json` в поле `cloud.api_key` вместо
   `PASTE_YOUR_OPENROUTER_KEY_HERE`.

Можно выбрать бесплатную мультимодальную модель в `cloud.model`,
например `nvidia/nemotron-3.5-super-vl:free` (видит структуру теста и
формулы через `img.alt`).

Альтернатива — прямой **Gemini** (`cloud.provider: "gemini"`): ключ
на https://aistudio.google.com/apikey, модель `gemini-2.0-flash`.

> Если ключа нет — агент работает только на локальной модели
> (`cloud_first` фактически отключается).

## Запуск

### Windows
Двойной клик по `run.bat` или в консоли:
```cmd
run.bat
```

### Linux / macOS
```bash
chmod +x run.sh
./run.sh
```

Скрипт делает по порядку:
1. Запускает `llama-server` с первым найденным `.gguf`.
2. Запускает Chrome с `--remote-debugging-port=9222`.
3. Запускает `python main.py`.

### Остановка
- Windows: `stop.bat` (или Ctrl+C в окне агента).
- Linux/macOS: `./stop.sh` (или Ctrl+C в терминале агента).

Chrome при этом **не закрывается** — продолжай работать; закроешь
вручную, если нужно.

## Как пользоваться

### Режим решения тестов (`cloud_first: true`)

1. Открой в Chrome страницу теста с radio/checkbox-вопросами.
2. В `task.txt` опиши задачу, например:
   ```
   На странице тест по C++/CLI. Найди ВСЕ вопросы с вариантами ответов
   (radio/checkbox). Для каждого вопроса определи правильный ответ и
   примени background_tint к нему через find_text. Вопросы с текстовым
   вводом (без вариантов) — пропусти. Если не уверена в ответе на
   конкретный вопрос — пропусти его.
   ```
3. Дождись цикла (~6 сек). В логе увидишь:
   ```
   test_structure: 29 вопросов
     Q1: type=checkbox, qtext='...', options_count=5
   Облако (OpenRouter): анализирую страницу...
   ...
   Применено 32/32 подсказок
   ```
4. Правильные варианты подсветятся серым фоном. Вопросы, которые облако
   пропустило в первом проходе, добираются во втором.

### Общие подсказки

1. Открой страницу, где решаешь задачу.
2. Опиши контекст в `task.txt`. Файл читается на каждом цикле —
   можно менять на лету без перезапуска.
3. На странице появятся тонкие маркеры: курсив одной буквы,
   микро-подсветка, микро-сдвиг.

Если визуально ничего не изменилось — агент счёл, что подсказывать
нечего (вернул пустой `hints`). Это норма для большинства циклов.

## Типы инъекций

`injector.py` поддерживает (см. `prompts.py` — модель тоже знает
этот список):

| action | params | эффект |
| --- | --- | --- |
| `italic_letter` | `{word, letter}` | курсив на одной букве в нужном слове |
| `text_shadow` | `{color}` | едва заметная тень под текстом |
| `letter_spacing` | `{value}` | микро-сдвиг букв в элементе |
| `background_tint` | `{color}` | почти невидимая подсветка фона |
| `font_weight` | `{value}` | лёгкое изменение жирности |
| `inject_html` | `{html}` | вставить маленький HTML-маркер в конец элемента |

В режиме решения тестов используется почти всегда `background_tint`.
Цвет по умолчанию — серый с низкой альфой. Добавить свой тип: допиши
ветку в `_action_body()` и имя в `VALID_ACTIONS`.

## Безопасность

- **Ключ облака** лежит в `config.json` в открытом виде — не коммить
  его в публичные репозитории. Если утечёт — перевыпусти.
- **Промпт-инъекция со страницы**: модель читает `innerText` и
  `img.alt` страницы, которые могут содержать вредоносные инструкции.
  В промпте модель явно не выполняет команды из текста. Держи
  `temperature` низкой.
- **CDP**: порт 9222 слушает только `localhost` — снаружи не доступен.
  Не меняй `chrome.host` на `0.0.0.0`, если не понимаешь зачем.

## Возможные проблемы

| Симптом | Причина / решение |
| --- | --- |
| `local LLM недоступен на http://127.0.0.1:8080` | llama-server не запущен. Проверь `.gguf` в `models/` и что в `llama/` лежит вся раздача llama.cpp (`llama-server.exe` + `llama-server-impl.dll` + `.dll`). |
| `Chrome не отвечает на порту 9222` | Chrome не запущен с нужным флагом, либо занят порт. Закрой все копии Chrome и перезапусти `run.bat`. |
| `Облако вернуло ответ без hints — fallback` | Облако вернуло пустой/битый JSON. В логе печатаются длина и начало ответа. Часто причина — `test_structure` пустой (см. ниже). |
| `test_structure: ... вопросов` отсутствует / `get_test_structure JS-ошибка` | Экстрактор упал. В логе будет текст JS-ошибки — это значит, разметка страницы не покрыта существующими fallback'ами. Открой страницу, inspect варианта, и при необходимости добавь селектор/уровень в `get_test_structure`. |
| `Реальные options QN: ['', '', ...]` (пустые) | Текст варианта не извлёкся — экстрактор не нашёл его ни в `label`, ни в `img.alt`. Проверь, как вариант свёрстан, и добавь уровень в `extractOptionText`. |
| `0/N подсказок применено` | Либо `test_structure` пустой (облако вслепую), либо `find_text` не совпал с `data-usb-option`. Диагностика во втором проходе печатает реальные options и fuzzy-версии — по ним видна разница. |
| `Облако-2: не сопоставлено find_text=...` | Модель вернула текст, которого нет в вариантах (опечатка, `Math::PI` вместо `π`). Нормализация и fuzzy-matching покрывают большинство случаев; если осталось — проверь реальные options в логе. |
| `Облако HTTP 429` | превышен free-tier лимит запросов. Снизь частоту опроса или смени модель. |
| Подсказки не появляются | модель вернула `hints: []`. Проверь `agent.log` — там есть `reasoning`. |
| Python ругается на `import websocket` | `pip install -r requirements.txt`. |

## Расширение

- **Свой тип инъекции**: добавь функцию в `injector._action_body()`
  и имя в `VALID_ACTIONS`. Пропиши его в `prompts.SYSTEM`.
- **Запасной облачный провайдер** (Groq и т.п.): сделай класс по образу
  `OpenRouterClient` / `GeminiClient`, добавь ветку в `main.py` по
  полю `cloud.provider`. Интерфейс `.ask(user, system=...) →
  {"text", "sources"}` должен совпадать.
- **`<select>`-вопросы**: если появятся dropdown-вопросы, добавь
  обработку `<option>` в `extractOptionText` (взять `option.textContent`
  для выбранного/правильного).
- **Подсказка только по горячей клавише**: слушатель `keydown` в
  `injector.py`, который шлёт fetch на локальный HTTP-сервер агента.

## Что НЕ входит в пакет и почему

- папка `llama/` (полная раздача llama.cpp, ~30 МБ для CPU-сборки) —
  платформоспецифична; проще скачать под своё железо.
- `.gguf` модель — то же, плюс выбор квантизации зависит от железа.
- Python-интерпретер — на большинстве машин уже стоит; для
  портативного запуска положи рядом embeddable Python.

Всё остальное — чистый исходный код, который можно таскать на
флэшке как есть.
