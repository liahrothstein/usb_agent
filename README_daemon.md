# Daemon mode + built-in hotkey

## Что изменилось

Раньше: каждый запуск `run.bat` убивал все Chrome-окна, поднимал llama-server,
чистил профайл Chrome, стартовал `python main.py` в polling-режиме.
Побочные эффекты:
- все вкладки Chrome умирали;
- приходилось вручную открывать нужный URL после каждого старта;
- скрипт обрабатывал только первую попавшуюся вкладку (а после —
  хэш-скип намертво блокировал повторную обработку той же вкладки).

Теперь: `run.bat` поднимает llama-server + Chrome + демон **один раз**.
Демон висит резидентно и сам слушает глобальный хоткей `Ctrl+Alt+Q` через
**Win32 `RegisterHotKey`** (ctypes, Python stdlib) — без ярлыков на рабочем
столе, без внешних программ (AutoHotkey/pynput больше не нужны). По хоткею:

1. Демон просыпается, берёт активную вкладку (первую page-type из `/json`,
   Chrome отдаёт их в MRU-порядке — обычно это и есть текущий таб),
   обрабатывает её с `force=True` (хэш-скип игнорируется),
   пишет результат в `agent.log`, засыпает обратно.

Хоткей и HTTP-триггер сосуществуют — оба работают одновременно.

Chrome и llama-server не перезапускаются — живут через перезапуски.

## Почему Win32 RegisterHotKey, а не pynput

Первая реализация использовала `pynput.keyboard.GlobalHotKeys`. Она **не
работала при русской раскладке**: pynput сопоставляет клавиши по **символу**
(`char`), а не по virtual-key code. При активном русском вводе физическая
клавиша Q генерирует `'й'`, и зарегистрированный `'<ctrl>+<alt>+q'`
(`char='q'`) просто не совпадал — хоткей молча не срабатывал.

`RegisterHotKey` регистрирует по **virtual key code** (`VK_Q = 0x51`), который
жёстко привязан к физической клавише и не зависит от языка ввода. Та же
клавиша срабатывает при русской, английской или любой другой раскладке.

Бонус: pure ctypes (stdlib), ноль внешних зависимостей — `run.bat` больше
ничего не ставит, папка самодостаточна. Windows Defender не ругается
(`RegisterHotKey` — легитимный Win32 API, не keyboard hook).

## Файлы

| Файл | Назначение |
| --- | --- |
| `main.py` | `--daemon` режим + `process_one_tab(force=True)` + встроенный хоткей через Win32 `RegisterHotKey` (ctypes) + HTTP-триггер |
| `run.bat` | проверяет `/health`, `/json/version`, `/trigger/health` перед стартом; не убивает Chrome если уже запущен; **не требует установки pynput** |
| `trigger.bat` | (опционально) `POST /trigger` на демон — альтернатива хоткею, если сочетание занято другой программой |

`cdp_client.py` **без изменений** — `pick_tab()` уже берёт MRU-первый таб.
Проблема была не в нём, а в хэш-скипе, который `force=True` обходит.

## Установка

1. Скопировать `main.py`, `run.bat`, `trigger.bat` в `D:\Development\usb_agent\`
   (поверх существующих — сохраните backup если хотите diffs).

2. (Опционально) Добавить в `config.json` поля `trigger_port` и `hotkey`:
   ```json
   "agent": {
     ...
     "trigger_port": 8765,
     "hotkey": "<ctrl>+<alt>+q"
   }
   ```
   Если не добавить — по умолчанию порт 8765, хоткей `Ctrl+Alt+Q`.
   Формат хоткея (pynput-совместимый, но регистрируется по VK):
   `<ctrl>`, `<alt>`, `<shift>`, `<cmd>` (Win), буквы/цифры/F-ключи как есть.
   Примеры: `"<ctrl>+<alt>+q"`, `"<ctrl>+<shift>+f12"`, `"<cmd>+<shift>+p"`.

3. Запустить `run.bat` один раз при старте сессии. Он:
   - поднимет llama-server (если не запущен);
   - поднимет Chrome на порту 9222 с чистым профайлом (если не запущен);
   - поднимет демон (`python main.py --daemon`).

Всё. Никаких ярлыков на рабочем столе, никакой AutoHotkey, никакого pynput,
ничего устанавливать вручную. Хоткей работает из коробки.

## Использование

1. Chrome открыт, демон работает (консоль `run.bat` висит).
   В `agent.log` (и в консоли) видно:
   ```
   Хоткей: <ctrl>+<alt>+q (Win32 RegisterHotKey, VK=0x51) — нажми для обработки активной вкладки. РаскладкаНЕважна (регистрация по VK, не по символу).
   Жду триггер... (переключись на вкладку с тестом и нажми хоткей)
   ```
2. Открываешь тест в любой вкладке (можно несколько вкладок с разными тестами).
3. Переключаешься на нужную вкладку.
4. Жмёшь `Ctrl+Alt+Q` (при любой раскладке — русской, английской, любой).
5. В `agent.log` видно:
   ```
   === Триггер получен — обрабатываю активную вкладку ===
   Вкладка: ... | ... (текст N симв., ...)
   test_structure: N вопросов
   ...
   Применено N/N подсказок
   === Готово — жду следующий триггер (Ctrl+Alt+Q или POST /trigger) ===
   ```

## Смена хоткея

Три способа (по приоритету):

1. **CLI (разовый запуск):**
   ```
   python main.py --daemon --hotkey "<ctrl>+<shift>+f12"
   ```

2. **config.json (постоянно):**
   ```json
   "agent": { "hotkey": "<ctrl>+<shift>+f12" }
   ```

3. **По умолчанию:** `<ctrl>+<alt>+q` если в config и CLI ничего не указано.

Формат (pynput-совместимый, но регистрируется по virtual-key code) —
модификаторы в угловых скобках через `+`, буквенные/цифровые клавиши и
F-ключи как есть. Примеры:
- `"<ctrl>+<alt>+q"` → Ctrl+Alt+Q (VK=0x51)
- `"<ctrl>+<shift>+f12"` → Ctrl+Shift+F12 (VK=0x7B)
- `"<cmd>+<shift>+p"` → Win+Shift+P (Win = `<cmd>`)
- `"<ctrl>+<alt>+<shift>+t"` → Ctrl+Alt+Shift+T
- `"<ctrl>+1"` → Ctrl+1 (цифры работают)

## Если хоткей не срабатывает

`RegisterHotKey` — легитимный Win32 API, Defender его не трогает. Если всё же
хоткей не работает:

1. **Проверь лог** `agent.log` — при старте демона должна быть строка:
   ```
   Хоткей: <ctrl>+<alt>+q (Win32 RegisterHotKey, VK=0x51) — ...
   ```
   Если вместо неё `RegisterHotKey не удался (GetLastError=...)` — сочетание
   уже занято другой программой (например, Ctrl+Alt+Q может перехватывать
   Windows или другая утилита). Смени хоткей через `config.json` или `--hotkey`.

2. **Проверь формат хоткея** в `config.json`. Должно быть `"<ctrl>+<alt>+q"`
   (в угловых скобках, через `+`), не `"Ctrl+Alt+Q"` и не `"ctrl+alt+q"`
   без скобок (скобки опциональны, но буква должна быть строчной или
   заглавной — регистр не важен, парсер нормализует).

3. **Раскладка не важна** — если хочешь убедиться, переключи раскладку на
   английскую и нажми снова. Если сработало только на английской — это баг
   pynput (старая версия), обновись до Win32-версии main.py (этой).

4. **Fallback без хоткея:** демон работает и без него — через HTTP-триггер.
   Двойной клик на `trigger.bat`, или PowerShell:
   ```powershell
   Invoke-WebRequest -UseBasicParsing -Uri 'http://127.0.0.1:8765/trigger' -Method POST
   ```

## Поведение при ошибках

| Ситуация | Что происходит |
| --- | --- |
| Жмёшь хоткей, демон не запущен | Ничего не происходит (слушатель мёртв вместе с демоном). Запусти `run.bat`. |
| `trigger.bat` при незапущенном демоне | `[WARN] Daemon not running on port 8765. Start run.bat first.` |
| Запускаешь `run.bat` второй раз, демон уже работает | `run.bat` видит `/health`, шлёт `/trigger` сам и выходит — второй демон не поднимается |
| Chrome упал | демон пишет `Chrome не отвечает на порту 9222 — жду`, ждёт; поднимешь Chrome вручную — следующий триггер сработает |
| llama-server упал | демон при триггере падает на локальной LLM; в cloud_first-режиме облако работает без локальной |
| Сочетание занято другой программой | `RegisterHotKey не удался (GetLastError=...)`; демон пишет warning и работает только по HTTP-триггеру. Смени хоткей. |

## Структура state между триггерами

Демон хранит в памяти:
- `last_page_hash` — хэш последней обработанной вкладки;
- `last_task_hash` — хэш последнего `task.txt`;
- `current_task` — текущий текст задачи.

При смене `task.txt` (отредактировали между триггерами) — `last_page_hash`
сбрасывается автоматически (лог `Задача обновлена: ...`).

`force=True` игнорирует `last_page_hash` — повторный триггер на той же
вкладке переобработает её (например, если первый прогон был неудачным или
модель дала не тот ответ).

## Что НЕ менялось

- `cdp_client.py` — без изменений.
- `injector.py`, `prompts.py`, `cloud*.py`, `llm_local.py` — без изменений.
- Polling-режим (`python main.py` без `--daemon`) — прежний, если вы
  хотите запустить старую одноразовую сессию без хоткея.
- `config.json` — совместим обратно (новые поля `trigger_port` и `hotkey`
  опциональны; формат hotkey pynput-совместимый, так что старое значение
  `"<ctrl>+<alt>+u"` если было — теперь регистрируется по VK и работает
  при любой раскладке).

Если что-то пошло не так — старый `main.py` и `run.bat` верните из backup,
запускайте `python main.py` (без `--daemon`) как раньше. Никаких других
изменений в кодовой базе нет.
